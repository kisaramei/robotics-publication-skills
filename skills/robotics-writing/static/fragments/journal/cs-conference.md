# Venue: CS/robotics conference — writing

Use for peer-reviewed computing, ML, CV, multimodal, embodied-AI, and robotics
conference submissions.

## Runtime venue contract

- Identify the exact venue, submission year, track, paper type, and review
  stage before applying format constraints.
- When exact requirements matter, consult the current official call for papers
  and author kit. Record the source and date checked.
- Treat page limits, anonymity rules, appendix/supplement policy, artifact
  rules, dual-submission policy, and permitted external links as runtime
  inputs. Never fill them from memory or from a prior year's template.
- If current official instructions are unavailable, ask the user for the
  author kit or mark the affected requirement as unresolved rather than guess.

## Writing defaults

- Make the technical contribution and its evidence legible within the main
  paper's actual review budget; do not hide claim-critical evidence in an
  appendix that reviewers may ignore or be barred from using.
- Keep Related Work separate when the venue/template expects it; otherwise
  integrate it only when that improves the argument and is permitted.
- State fair-comparison conditions, ablations, compute/hardware, variance, and
  failure modes at the point where reviewers need them.
- Preserve anonymity until the current venue rules establish what identifying
  repositories, acknowledgements, prior versions, or project pages permit.
